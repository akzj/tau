## §1 — ToolSchema Interface

```go
package core

type ToolSchema interface {
    Marshal() (json.RawMessage, error)        // → LLM-facing JSON Schema
    Validate(raw json.RawMessage) (any, error) // ← LLM-returned JSON, validated + decoded
}
```

**Three-in-one contract**: A single `ToolSchema` value provides the Go-side typed struct, the LLM-facing JSON Schema, and the runtime validator. No separate schema definition, no struct-tag drift, no hand-written validator that falls out of sync.

This is the Go equivalent of pi's TypeBox `Type.Provider({ schema, validate, decode })` — with one critical difference: tau makes the JSON Schema the **source of truth**, not the Go struct.

## §2 — B9 Decision: Schema-First Codegen

**Decision** (Phase 2 §4, PoC-verified): **schema-first codegen**, using `atombender/go-jsonschema` as the initial generator.

### Why codegen won

| Dimension | reflect+jsonschema | **schema-first codegen** | struct-tag + hand validator |
|-----------|-------------------|-------------------------|---------------------------|
| Discriminated union (`oneOf`) | ❌ structural impossibility | ✅ full support | ⚠️ hand-written, drift-prone |
| R3 (doc-lint sync) | ⚠️ derived schema, not source | ✅ schema is source, CI `go generate` diff | ❌ 2-place change, guaranteed drift |
| LLM adversarial resistance | ❌ no `oneOf` → vulnerable to prompt injection | ✅ OpenAI gpt-5.4 resisted induction (PoC) | ⚠️ relies on training priors |
| DX (adding a field) | ✅ 1 place | ⚠️ 1 place + `go generate` | ❌ 2 places |

### PoC results (Phase 2 §4)

3 approaches × 2 models × 2 cases = 12 happy-path + 6 adversarial tests:
- **Happy-path**: all three approaches equivalent (indistinguishable).
- **Adversarial** (prompt engineered to induce schema violations): only codegen resisted — `oneOf` + `const` discriminator forced LLM to stay within schema. Reflect couldn't express `oneOf` at all.

### Known trade-offs

- **`go generate` step**: adds one command before `go build`. IDE integration is mature (gopls, GoLand); cost ≈ 0 for daily workflow.
- **Union types degrade to `[]interface{}`**: `atombender` maps `oneOf` to `[]interface{}` in Go, requiring type-switch at call sites. Awkward but correct.
- **Follow-on**: tau may write a ~50-line custom codegen that outputs typed sum-types with type-switch helpers. Trigger: Phase 5+ product layer first hits the `[]interface{}` pain point. Start with `atombender`.

**Caveat** (Anthropic gateway): PoC used a proxy gateway, not Anthropic official API. `oneOf` enforcement was not isolated between protocol and gateway. **Phase 5+ must re-verify with Anthropic official API + strict mode**. If Anthropic protocol layer doesn't enforce `oneOf`, the decision stands (OpenAI evidence is sufficient), but product layer will need an Anthropic-specific runtime validation fallback.

## §3 — `toolspec/` Workflow

```
toolspec/my-tool.schema.json   ← source of truth (hand-authored or generated)
    │
    ▼  go generate
toolspec/my-tool_gen.go        ← typed Go struct + Marshal/Validate + UnmarshalJSON
    │
    ▼  implements ToolSchema
core.Tool{Schema: mytool.Schema}
```

### Schema authoring rules

- Use JSON Schema draft-2020-12.
- Discriminated unions use `oneOf` + `const` discriminator (required by codegen).
- CI runs `go generate ./... && git diff --exit-code` — any uncommitted generated code change fails the build (R3 enforcement).
- Generated files carry `// Code generated by ... DO NOT EDIT.` header.

### Example schema

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "action": { "type": "string", "enum": ["create", "delete", "edit"] },
    "path":    { "type": "string" },
    "content": { "type": "string" }
  },
  "required": ["action", "path"],
  "allOf": [
    { "if": { "properties": { "action": { "const": "edit" } } },
      "then": { "required": ["content"] } }
  ]
}
```

## §4 — Alternatives Rejected

### reflect+jsonschema (`invopop/jsonschema`)

**Rejected** because discriminated unions are structurally impossible with Go reflection alone. `interface{}` fields with type-tags can express variants, but the generated JSON Schema lacks `oneOf` + `const` — the single feature that resists adversarial LLM inputs. Today's simple tools work; the first discriminated union requires migration to codegen anyway.

### struct-tag + hand-written validator

**Rejected** because it splits the truth across two locations (struct tags + JSON Schema file). Adding a field requires changing both; forgetting one creates silent drift. Phase 1 handoff D3 warned: "meta-debt = no-lint-guarded paper rule." This path embodies that risk.
